TurfDart is a Dart library for [spatial analysis](https://en.wikipedia.org/wiki/Spatial_analysis). It includes traditional spatial operations, helper functions for creating GeoJSON data, and data classification and statistics tools. You can use TurfDart in your Flutter applications on the web, mobile and desktop or in pure Dart applications running on the server.

As the foundation, we are using [Geotypes](https://github.com/dartclub/geotypes), a lightweight dart library that provides a strong GeoJSON object model and fully [RFC 7946](https://tools.ietf.org/html/rfc7946) compliant serializers.

Most of the functionality is a translation from [turf.js](https://github.com/Turfjs/turf), the progress can be found [here](Progress.md).

## Get started

- Get the [Dart tools](https://dart.dev/tools)
- Install the library with `dart pub add turf`
- Import the library in your code and use it. For example:

```dart
import 'package:turf/helpers.dart';
import 'package:turf/src/line_segment.dart';

Feature<Polygon> poly = Feature<Polygon>(
  geometry: Polygon(coordinates: [
    [
      Position(0, 0),
      Position(2, 2),
      Position(0, 1),
      Position(0, 0),
    ],
    [
      Position(0, 0),
      Position(1, 1),
      Position(0, 1),
      Position(0, 0),
    ],
  ]),
);

void main() {
  var total = segmentReduce<int>(
    poly,
    (previousValue, currentSegment, initialValue, featureIndex,
        multiFeatureIndex, geometryIndex, segmentIndex) {
      if (previousValue != null) {
        previousValue++;
      }
      return previousValue;
    },
    0,
    combineNestedGeometries: false,
  );
  print(total);
  // total ==  6
}
```

### Notable Design Decisions

- Nested `GeometryCollections` (as described in
  [RFC 7946 section 3.1.8](https://datatracker.ietf.org/doc/html/rfc7946#section-3.1.8))
  are _not supported_ which takes a slightly firmer stance than the "should
  avoid" language in the specification

## Polygon clipping

`polygonIntersect`, `union` and `difference` take a `FeatureCollection` of
`Polygon`s and `MultiPolygon`s and return a `Feature` with a `Polygon` or
`MultiPolygon`, or `null` for an empty result, as in turf.js v7. turf.js'
`intersect` is called `polygonIntersect` here, because the `lineclip` module
already exports an `intersect` function.

The clipper is a port of [polygon-clipping](https://github.com/mfogel/polygon-clipping)
and [polyclip-ts](https://github.com/luizbarboza/polyclip-ts), the library behind
turf.js v7. It computes with the same exact decimal arithmetic as polyclip-ts, so
results match turf.js, on the Dart VM and on the web. Coordinates are planar
(lng/lat), as in turf.js.

```dart
final remaining = difference(FeatureCollection(features: [district, park]));
```

`mask(polygons, mask: frame)` returns the frame with the polygons cut out, as
turf.js does: holes of the polygons are dropped, so they stay unshaded. Pass
`keepHoles: true` to get `frame − polygons` instead, which shades the holes too.

## Tests and Benchmarks

Tests are run with `dart test` and benchmarks can be run with
`dart run benchmark`

Any new benchmarks must be named `*_benchmark.dart` and reside in the
`./benchmark` folder.

Fixture suites that also run in the browser (`dart test -p chrome`) read
their GeoJSON from Dart files generated by `dart run tool/embed_fixtures.dart`;
regenerate them after changing files under `test/examples/<module>`.
Property tests take their number of runs from `TURF_FUZZ_RUNS` (default 200).
